## 1. YOSHILOVER の提供価値(1文)

**巨人ファンが、大手記事だけでは追いきれない二軍・若手・登録動向・データ小ネタを、毎日ざっくり確認できる巨人特化の速報メモ置き場。**

- **再訪理由**: 大手が薄い 二軍・若手・登録動向・巨人特化データ を、毎日軽く確認できること。
- 一軍結果だけなら大手で足りるが、YOSHILOVER は「二軍・若手・登録・データ小ネタ」まで拾うことで再訪理由を作る。
- (背負いすぎ回避)「巨人の全部」「大手より広く」とは言わない。範囲を広げすぎると運用負荷・読者期待・品質責任が重くなるため、**大手が薄い領域を軽く拾う** に留める。

## 2. X で狙う役割(3種)

| 型 | 狙い | 中身 | リンク |
|---|---|---|---|
| 普通ポスト | 共感・ファン心理・試合中の熱量 | 勝敗の感情、1シーン、若手の躍動への一言 | なし(心理を動かす) |
| 記事リンク | 事実整理・データ・あとで見返す | 登録/transaction、独自データ、二軍まとめ | あり(確認したい情報へ) |
| データ/SNS hub | 再訪・保存・回遊 | `/data/` 選手ページ・球団ランキング、SNSリアルタイムページ | あり(「保存先」として案内) |

- hub は固定ツイ / プロフィール / 投稿の締めの一言で「巨人データはここに溜まってる」と置いておくだけ(毎回宣伝しない)。

## 3. 現在の記事候補の分類(直近30本の実例 = 型として使う)

毎回 Claude が分類し直すのではなく、**この型に当てはめれば user が即判断できる** ことを目的とする。

| バケット | 型 | 直近の実例 |
|---|---|---|
| ① すぐX投稿してよい | 独自データ / 登録系 / 若手躍動+数字 | 「キャベッジ 打点5でセ2位」「大城 対右0.364でセ3位」「西舘勇陽 今季初昇格・田和廉抹消」「浅野翔吾 猛打賞(2軍)」「山城京平 5回1失点」 |
| ② 投稿文を足せば使える | 試合結果(熱量/采配の一言を足す) / 1シーン動画(普通ポスト化) / 球団順位データ(切り口を足す) | 「ダルベック適時打・浦田3盗塁」「浅野ナイスキャッチ(1シーン)」「セ球団打率 巨人4/6位」「日ハム戦 4-2勝利(単純結果)」 |
| ③ 記事として残すがX投稿しない | 告知のみ / 驚きの弱い細かいデータ / 外部コラム転載寄り | 「テレビ・ラジオ中継情報」「丸 1・3塁時の打点2で巨人内1位」「岡田彰布コラム(週ベ)」 |
| ④ 弱い / 重複 / 見送る | 大手の単純後追い / 他球団視点 / 直近重複 | 「徳光和夫 監督代行に期待」「現ドラ菊地 古巣に恩返し(他球団主語)」「森田登録の重複群」「伊原コラム重複(同記事2本)」 |

> **試合結果の扱い**: 単純な勝敗だけなら大手で足りるため ②(熱量/采配の一言を足す)〜③ 寄り。**データ・若手・采配・登録 などの追加視点がある時だけ ①**。YOSHILOVER の強みに寄せる。

> 観察: 直近は **二軍・若手・登録・独自データ** が候補の主流で、これは §1 の提供価値と一致している(=強み通りに記事が出ている)。弱いのは中継告知・外部コラム・他球団主語・重複。

## 4. 投稿する記事の条件(最大5)

1. 巨人ファンが今すぐ反応できる(勝敗・若手・登録・記録)
2. 選手名 / 試合 / 数字 / 登録 / 二軍 のどれか具体がある
3. 大手の単純後追いでなく、**見方・整理・データ・二軍/若手** という独自軸がある
4. (リンク投稿時)投稿文だけでリンク先を見る理由が伝わる
5. 誤情報リスクが低い(出典・数字が記事内で確認できる)

## 5. 投稿しない記事の条件(最大5)

1. 大手の見出しコピーに近い / 外部コラムの転載寄り
2. 情報が薄い・告知のみ(中継情報など)
3. 直近に同内容を投稿済み / 記事が重複
4. 巨人ファンの感情が動きにくい(他球団主語・巨人relevance薄)
5. リンク先に投稿文以上の追加価値がない

## 6. 1週間の実験(KPI 3つだけ)

1. **投稿本数**(日次)
2. **反応が良かった投稿タイプ**(普通 / リンク / hub のどれか、ざっくり印象で可)
3. **投稿した / 見送った / 迷った 候補数**(3つの数だけ)

- GA4・hub到達・選別時間は **余裕がある時だけ**。記録を増やさない。
- 記録は1日1行で十分(例: `6/2 投稿4 / 良かった=データ系リンク / 投稿4・見送り6・迷い2`)。
