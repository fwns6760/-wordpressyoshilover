## 1. 使えるデータ資産の棚卸し(実測)

production `insight.db`(一軍 NPB box-score ベース、全12球団を順位 baseline 用に収録)。

### 使える(構造データあり)

| 資産 | 実体 | 規模 | 備考 |
|---|---|---|---|
| 一軍試合結果 | `games`(スコア/勝敗/先発勝敗/セーブ/1行サマリ) | 314試合 | 一軍のみ。二軍は無し(下記) |
| 選手別 打撃 | `batting_logs`(AB/R/H/RBI/SB + イニング別打席 atbats_json) | 5,652行 | player_canonical で巨人選手抽出可 |
| 選手別 投球 | `pitching_logs`(IP/H/K/BB/ER/球数/result/登板回) | 2,559行 | |
| **直近成績 + 順位**(最強資産) | `advanced_metric_snapshots`(選手×scope×metric、league_rank/position_rank/sample_size 付き) | **312,657行** | scope = last_3/5/10/20試合・7d/30d・monthly・weekly・season。AVG/OBP/SLG/OPS/ISO/K%/BB%/ERA/WHIP/K9 等 |
| **自動検出シグナル**(データ小ネタの源泉) | `article_candidates`(signal_type/magnitude/baseline→current/window/priority) | **69,744件** | hit_streak・連打・本塁打・hot・多安打・打順jump・初打順・milestone・zscore outlier 等 |
| 打順 / 起用 | `lineups`(打順/守備位置/左右) | 2,826行 | |
| 試合の分岐点 | `inning_scores`(イニング別得点 + total) | 366行 | どの回に得点/失点したか |
| データページ(hub) | `/data/` 個別115選手 + cluster | index 稼働 | season/直近5/打順別/対球団/球場別/序中終盤/連続/投手 |
| SNSリアルタイム(hub) | `/data/` 配下 1軍/farm 2ページ | index 稼働 | X集約 |

### 取れない / 弱い(正直に明記)

| 項目 | 状態 | 理由 |
|---|---|---|
| 二軍の構造化 box-score(二軍試合結果/二軍選手成績) | **構造データ無し** | `games.league_label` 全None、game_id に farm 判別なし。二軍情報は **記事テキスト由来**(数値は記事から拾う) |
| W-L リーグ順位表 / ゲーム差 | **未収録** | `standings_snapshots` 0行。※ 球団の打率/防御率 等 **rate ランキングは computed で publish 済** |
| 対右/対左・得点圏(RISP)・カウント別 | **現状BLOCKED** | `at_bat_details.batter_canonical` 全NULL(447、Phase A backfill 待ち) |
| サバメ指数(FIP/wOBA/BABIP/xFIP)・守備UZR/RF | **publish NG** | DB には存在するが whitelist 除外([[project_data_insight_final_whitelist_2026_05_15]])。今回も使わない |

> 含意: いま **正確に・低リスクで出せるのは「一軍 box-score 由来のデータ小ネタ」**。二軍の数値型は記事テキスト curation に頼るため、数値の出典確認コストが高い。今週は一軍データ型に寄せるのが安全。

## 2. 今すぐ作れそうなデータコンテンツ型(候補)

DB資産から実際に組める型のみ(新規実装・source拡張なしで手動運用可能なもの)。

1. 今日の巨人データ小ネタ(順位・記録)
2. 直近7試合(5試合)で伸びている選手
3. 起用の理由がわかるデータ(打順・登録の意味)
4. 連続記録・マイルストーン到達
5. 試合の分岐点データ(どの回で決まったか)
6. セ・リーグ内 rate 順位で見る巨人の強み/弱み
7. 二軍で状態が上がっている選手(記事テキスト由来)
8. データで見る次に注目したい選手(事実ベース、予測にしない)

## 3. 各型の整理

| 型 | 使うデータ | Xで反応される理由 | 投稿例 | 誤情報リスク | 手動運用可否 | 将来自動化可否 |
|---|---|---|---|---|---|---|
| ① 今日の巨人データ小ネタ(順位・記録) | advanced_metric_snapshots(league_rank/position_rank) | 具体数字+「セ◯位」で即わかる・自慢/嘆きの種 | 「キャベッジ 打点5でセ2位(直近5試合)」 | **低**(box-score由来) | ◎ | 既に一部自動 publish |
| ② 直近7試合で伸びている選手 | snapshots(scope=last_5_games/last_7d、season比) | 「今が旬」の選手が毎日変わる=再訪理由 | 「大城卓三 対右.364でセ3位(直近10試合)」 | 低〜中(小標本→sample_size併記必須) | ◎ | 可 |
| ③ 起用の理由がわかるデータ | lineups + 打順別成績(/data/) + lineup_slot signal | 「なぜこの打順/起用?」の答えは大手が薄い | 「6番起用の◯◯、直近6番で.320 ─ 説明のつく抜擢」 | 低 | ◯(打順別は既出) | 可 |
| ④ 連続記録・マイルストーン | article_candidates(hit_streak/milestone)+ batting_logs | 記録は「あと何本」で追いたくなる | 「◯◯ 3試合連続マルチ安打」 | 低 | ◎ | 済(signal) |
| ⑤ 試合の分岐点データ | inning_scores + games | 試合の山場を1枚で再確認できる | 「今日は5回の3得点が分岐点(0-0→3-0)」 | 低 | ◯(試合後) | 可 |
| ⑥ セ内 rate 順位で巨人の強み/弱み | batting/pitching_logs 集計(球団 ranking) | チーム全体の立ち位置=ファンの関心軸 | 「巨人 球団防御率 セ4/6位 3.48」 | 低 | ◯(既に publish) | 済 |
| ⑦ 二軍で状態が上がっている選手 | RSS記事テキスト(二軍速報) | 大手が最も薄い領域=独自性が高い | 「2軍◯◯ 5試合で打率.380、昇格圏」 | **中**(構造データ無し→数値の出典確認が必須) | ◎ | ✕(farm ingest=source拡張、今回HOLD) |
| ⑧ 次に注目したい選手(事実ベース) | anomaly zscore / hot batter signal | 「予習」needs、軽い | 「直近で球団内 出塁率トップは◯◯」 | 中(予測に寄せると破綻→事実に留める) | ◎ | 可 |

## 4. 優先3型

優先基準(反応しやすい/大手が深追いしない/再訪理由/データ差別化/誤情報低/手動1週間試せる)で選定。
**いずれも一軍 box-score 由来=正確・低リスク**で、サバメ・予測・二軍構造データの穴を避ける。

1. **① 今日の巨人データ小ネタ(順位・記録)**
   - 最強資産(snapshots 31万行)をそのまま使え、誤情報リスク最小、ネタが毎日切れない。大手は順位を毎日は出さない。
2. **② 直近7試合で伸びている選手**
   - 「今が旬」が毎日変わる=再訪理由そのもの。data 差別化が効く。sample_size 併記で誇張を防げば低リスク。
3. **③ 起用の理由がわかるデータ(打順・登録の意味)**
   - 大手は「結果」は出すが「なぜこの起用か」のデータ的裏づけは薄い。巨人ファンが一番気になる軸で、`/data/` 打順別ページへの再訪にも繋がる。

> ⑦二軍は独自性は最高だが構造データが無く誤情報コストが高いため、今週は外す(記事テキスト curation で将来別途)。

## 5. 今週やる最小施策(1つだけ)

**「今日の巨人データ小ネタ」を 1日1〜2本、手動でX投稿する。**

### 投稿対象は以下の3型に限定する

| 型 | 中身 | 例 |
|---|---|---|
| 順位・記録型 | リーグ上位 / チーム内上位 / 連続記録 / milestone | 「キャベッジ 打点 セ2位」「◯◯ 3試合連続マルチ安打」 |
| 直近変化型 | 直近7試合で伸びている / 最近数字が上がっている選手 | 「大城卓三 直近10試合 対右.364」 |
| 起用理由型 | 打順 / スタメン / 捕手 / 代打 / 継投 などの起用を数字で補足できるもの | 「6番起用の◯◯、直近6番で.320」 |

### 投稿文は必ずこの型にする

```
数字：
意味：
巨人ファン向けの一言：
```

例:
```
数字：キャベッジ打点セ2位
意味：巨人打線で「返す役割」が見えやすい
一言：試合後にこういう数字を見ると、印象がかなり変わる
```

### なぜこれか / やらないこと

- **ゼロ実装**(既存資産そのまま)・**誤情報リスク最小**(一軍 box-score 由来)・**ネタが切れない**。
- ネタ元: `advanced_metric_snapshots` の league_rank/position_rank 上位、`article_candidates` の hit_streak / milestone、`lineups` + 打順別成績。
- **二軍・若手**: 独自性は高いが、現時点では構造化 box-score が無いため **今週の自動/準自動データ施策からは外す**。ただし **記事テキスト由来で出典確認できるものは「手動候補」として残す**(数値は記事から拾い、出典を必ず確認)。二軍構造データ化は将来課題(§6 HOLD)。
- やらないこと: 二軍数値の手作り、サバメ、予測フレーム、新規 source、自動投稿。

### KPI(増やさない)

- 448 の3つ(投稿本数 / 効いた型 / 投稿・見送り・迷い数)のまま。**記録時に「投稿タイプ」だけ付ける**。
- 例: `6/2 投稿2 / 良かった=直近変化型 / 投稿2・見送り5・迷い1`
- 1週間後に「3型のどれが効いたか」を振り返り、②③型へ広げるか判断。
